Project Summary

📖 DevOps Journey – From Zero to Cloud

This is a self‑contained, self‑paced study roadmap designed to build genuine, production‑ready foundations before touching any cloud infrastructure. The goal is not just to pass certifications but to internalise the core concepts that every DevOps engineer needs – no shortcuts, no black‑box magic, just deep understanding through practice.

The entire journey is divided into two clear phases, each with its own milestones and deliverables. All notes are written in Markdown, version‑controlled on GitHub, and published as an interactive website (the one you're looking at) with flashcards, quizzes, and progress tracking.

I

🎯 Phase 1 – Foundations (5 pillars)

Duration: ~3‑4 months (self‑paced) · Pre‑requisites: None – absolute beginners welcome.

  • 🌐 Pillar 1 – Networking Fundamentals (complete)
    OSI & TCP/IP models, IPv4/IPv6, subnetting, CIDR, VLSM, routing & switching, DNS, TCP/UDP, network security, RJ45 cabling. Why it matters: Every system you'll ever touch lives on a network. You cannot secure, scale, or troubleshoot what you don't understand.
  • 🐧 Pillar 2 – Linux & CLI Proficiency (in progress)
    Filesystem navigation, file operations, permissions, processes, SSH, package management, bash scripting, systemd, text processing (grep/sed/awk), networking commands.
    Why it matters: Linux runs the cloud. Every server, container, and virtual machine speaks Linux – your terminal is your primary weapon.
  • 🔒 Pillar 3 – Security Concepts (locked)
    Encryption (symmetric/asymmetric), TLS/SSL, PKI, hashing, authentication, least privilege, OWASP Top 10, secure defaults.
    Why it matters: Security is everyone's responsibility. You cannot design safe systems without knowing the threats and the controls.
  • ⚙️ Pillar 4 – Scripting & Automation (locked)
    Python fundamentals, Bash scripting, file I/O, REST APIs, JSON parsing, automation patterns, error handling.
    Why it matters: Automate everything. The difference between a good engineer and a great one is the ability to script repetitive tasks.
  • 🗄️ Pillar 5 – Databases & Storage (locked)
    SQL vs NoSQL, normalisation, indexing, ACID properties, transactions, caching strategies, CAP theorem, backup & recovery.
    Why it matters: State is hard. Databases are at the heart of almost every application – understanding them prevents catastrophic data loss.
II

🚀 Phase 2 – DevOps Roadmap (after SAA)

Once Phase 1 is complete and the AWS Solutions Architect Associate (SAA) certification is earned, the full roadmap.sh/devops is followed:

  • 🐳 Docker & Containers – images, Dockerfile, Compose, registries
  • 🔁 CI/CD Pipelines – GitHub Actions, GitLab CI, Jenkins
  • ☸️ Kubernetes – pods, deployments, services, ingress, Helm
  • 🏗️ Infrastructure as Code – Terraform, Ansible, CloudFormation
  • 📊 Monitoring & Observability – Prometheus, Grafana, Loki, tracing
  • 🔁 GitOps – ArgoCD, Flux
III

📐 Methodology & Learning Principles

  • Foundations first: No AWS, no cloud abstractions until the raw concepts are mastered. Every topic is studied from first principles – e.g., subnetting by hand before touching a VPC.
  • Hands‑on, not passive: Each section includes practical labs, exercises, and quizzes. Theory without practice is forgotten.
  • Public & versioned: All notes are committed to GitHub (Great_Cheatsheets repo). The website (DevOps‑Journey repo) is built pillar by pillar – flashcards, self‑grading quizzes, and progress rings are part of the learning experience.
  • Spaced repetition: Key concepts are highlighted and revisited across pillars. The site remembers your progress (localStorage) and congratulates you on milestones.
  • Real‑world relevance: Every concept is explicitly connected to the DevOps tools and AWS services that will use it – but only after the foundation is solid.
