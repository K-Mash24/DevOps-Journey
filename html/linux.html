Filesystem Structure & Navigation

A filesystem is the system that organises data on disk into a structured hierarchy. On Linux, this is a single tree with one root — everything lives under it. Unlike Windows, which gives each disk its own tree (`C:\`, `D:\`), Linux has one tree for everything.

The top of the tree is written as / (called "root"). All files, directories, and devices live somewhere below it.

DirectoryPurpose
/Root — top of the entire filesystem tree
/homeHome directories for regular users (e.g. /home/codespace)
/rootHome directory for the root (admin) user — separate from /home
/etcSystem-wide configuration files (human-readable text)
/varVariable data — grows while system runs (logs, caches)
/usrInstalled programs and their supporting files
/tmpTemporary files — cleared on every reboot
/binEssential command binaries (ls, cd, pwd, etc.)
/devDevices represented as files (disks, terminals, etc.)
SymbolNameWhat it is
/RootTop of the entire filesystem tree
~TildeShortcut for your home directory (/home/codespace)
.DotCurrent directory
..Dot-dotParent directory — one level up
/rootRoot's homeThe admin user's home — not the filesystem root
Common confusion: ~ and /root are completely different things. ~ expands to your own home (/home/codespace). /root is a specific directory that belongs to the admin user.
pwd                 # Print Working Directory — shows your current location
ls                  # List contents of current directory
ls -l               # Long format — permissions, owner, size, date
ls -a               # All files including hidden
ls -la              # Long format + hidden (most common combo)
cd /etc             # Change to /etc (absolute path)
cd ..               # Go up one level
cd ~                # Go to your home directory
cd -                # Go back to the previous directory
Reading ls -l output: drwxr-xr-x 2 alice users 4096 Jun 3 10:30 Documents
First character: d=directory, -=regular file, l=symlink. Then 9 permission characters (user/group/other).

Absolute path: Full address starting from root, always starts with /. Works the same no matter where you are.

Relative path: Address starting from your current working directory. Uses . and ...

cd /home/codespace/projects   # absolute
cd projects                    # relative — only works if 'projects' exists in current dir
cd ../..                       # go up two levels
The key rule: A relative path only works if the target exists inside your current directory.

Any file or directory whose name starts with . is hidden. Hidden = not shown by default in ls. Not protected or encrypted — just kept out of the way.

ls -a ~                # reveal hidden files in home
tree ~ -L 2            # show tree structure, 2 levels deep
tree -a ~              # include hidden files
File/DirPurpose
.bashrcBash shell config — runs every time a terminal opens
.gitconfigGit settings — name, email, preferences
.ssh/SSH keys and known hosts

File & Directory Operations

touch notes.txt                    # creates empty file (or updates timestamp)
echo "hello world" > notes.txt    # writes content, overwrites entire file
echo "another line" >> notes.txt  # appends to file, preserves existing content
Warning: > is destructive — it wipes the entire file, not just one line.
mkdir projects
mkdir -p projects/linux/section-2   # creates full nested path in one shot

-p creates all missing parent directories along the way. Without it, mkdir a/b/c fails if a/b doesn't already exist.

cp notes.txt backup/
cp -r projects projects-backup      # -r required for directories
cp -i notes.txt backup/             # interactive — asks before overwriting
mv notes.txt archive/               # move into directory
mv old-name.txt new-name.txt        # rename in same location
mv -i notes.txt archive/            # interactive — asks before overwriting
Unlike cp, mv leaves no copy behind — the original is gone. mv doesn't need -r for directories.
rm notes.txt                         # delete a file
rm -r projects/                      # delete a directory and all its contents
rm -rf projects/                     # force delete — no prompts, no mercy
rmdir empty-dir/                     # only works if the directory is empty
Warning: Linux has no recycle bin. Deleted = gone permanently. rm -rf is irreversible.
rm *.log                               # delete all .log files
cp *.txt backup/                       # copy all .txt files
ls file-?.txt                          # matches file-1.txt, file-a.txt (exactly one char)
Caution with rm *: Always run ls * first to see what you're about to delete.
cat notes.txt                          # print entire file to screen (good for short files)
less notes.txt                         # scrollable viewer (Space=down, b=up, q=quit)
head -n 5 notes.txt                    # first 5 lines
tail -n 5 notes.txt                    # last 5 lines
tail -f app.log                        # follow — prints new lines as file grows

tail -f is essential for watching log files in real time.
